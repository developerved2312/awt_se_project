HaritAyan is an all-in-one smart agriculture and city cooling platform built specifically for farmers and urban planners in Vadodara District, Gujarat. Instead of forcing farmers to navigate complicated, separate government portals, HaritAyan connects everything into a single, straightforward system:

🌿 Module 1: Plant Disease Vision Scanner (Dual-Engine AI)
AI Computer Vision • Edge & Cloud
🎯 What It Does (In Simple Words)
A farmer takes a photo of an unhealthy crop leaf (Cotton, Castor, Pigeon Pea/Tuver, Tomato, or Okra). The system immediately identifies the disease (fungal spots, blight, virus, or insect damage) and provides simple, low-cost organic remedies (such as Neem oil or sour buttermilk spray) in both English and Gujarati. It works completely offline using an in-browser edge AI model, and automatically connects to Google Gemini 1.5 Pro AI when internet is available for in-depth agronomic advice.
📥 Where Data Comes From
  • Leaf Photo: Captured directly via smartphone camera or uploaded from gallery (JPEG/PNG up to 10MB).
  • Target Crop: Farmer selects crop name (Cotton, Castor, Pigeon Pea, Tomato, Okra).
  • Offline Edge AI: MobileNetV2 neural network runs inside the browser with TensorFlow.js (zero internet required).
  • Cloud AI: Image buffer sent to Google Gemini 1.5 Pro API when online.
⚙️ How Processed & Backend Files
  • backend/src/routes/scanRoutes.js: Maps POST /api/scan and GET /api/scan/history.
  • backend/src/middleware/uploadMiddleware.js: Multer middleware verifies file type and buffers the image.
  • backend/src/controllers/scanController.js: Calls Gemini API or offline rules to classify the disease and extract treatments.
  • backend/src/services/geminiService.js: Prompts Gemini to respond in clean JSON with English and Gujarati remedies.
💾 Where Data is Stored
  • MongoDB Atlas Collection: scans
  • Mongoose Model: backend/src/models/Scan.js
  • Stored Schema Fields: userId, crop, disease, confidence, severity, symptoms (EN/GU), organicRemedies (EN/GU), imageUrl, diagnosedAt, inferenceEngine.
  • Offline Fallback: Scans saved in browser localStorage('haritayan_scan_history').
🖥️ How Displayed on Screen
  • frontend/src/pages/PlantScanner.jsx: Upload box, camera viewfinder, engine toggle switch (Offline Edge vs Cloud Gemini), circular confidence gauge.
  • Diagnosis Card: Shows disease name in English & Gujarati, severity badge (Low/Medium/High), and natural step-by-step remedies.
  • frontend/src/services/tfjsModelService.js: Runs MobileNet neural weights directly in the client browser.
🔄 Step-by-Step Data Flow Pipeline
1 Farmer snaps a photo of a spotted cotton leaf on PlantScanner.jsx.
2 If offline, tfjsModelService.js classifies it in-browser; if online, scanService.js sends it to POST /api/scan.
3 scanController.js sends the image to Gemini 1.5 Pro, receiving structured disease data and remedies in English and Gujarati.
4 The result is saved to MongoDB Atlas collection scans using Scan.create().
5 The screen displays the disease name ("Cercospora Leaf Spot / પાનના ટપકાનો રોગ"), 94% confidence, and instructions to spray 5% Neem oil.
🌳 Module 2: Urban Heat & 3D Tree Canopy Simulator
Thermal Simulation & Three.js 3D
🎯 What It Does (In Simple Words)
Shows summer surface temperatures across 8 city wards in Vadodara (Sayajigunj, Alkapuri, Makarpura, Manjalpur, Karelibaug, Gotri, Gorwa, Waghodia Road). Citizens and municipal planners can drag a tree-planting slider to simulate planting native shade trees (Neem, Peepal, Banyan, Jamun) and instantly see the simulated cooling effect (up to 3.4°C cooler) on both an interactive 2D map and an animated 3D tree canopy view.
📥 Where Data Comes From
  • Satellite Heat Baselines: Measured surface heat baselines for Vadodara municipal wards (calibrated from Landsat thermal sensors).
  • Live Weather: Real-time air temperature, humidity, and solar radiation from the Open-Meteo API.
  • Tree Cooling Multipliers: Natural cooling power (evapotranspiration and shade index) of native Gujarat trees.
  • User Inputs: Ward selector, tree slider (0 to 50,000 trees), and species dropdown.
⚙️ How Processed & Backend Files
  • backend/src/routes/heatRoutes.js: Exposes endpoints GET /api/heat/wards and POST /api/heat/simulate.
  • backend/src/controllers/heatController.js: Runs cooling math: Cooling ΔT = -α · ln(1 + treeCount / 5000) · speciesFactor.
  • Calculates ward heat vulnerability levels: Low (Green), Moderate (Yellow), High (Orange), Severe (Red).
💾 Where Data is Stored
  • Ward Master Data: Ward coordinates, baseline temperatures, and green vegetation index (NDVI) stored in heatController.js.
  • System Telemetry: Cached cooling observations recorded in MongoDB Atlas systemmetrics.
  • Browser State: Active ward selection and simulated temperature kept in React component state.
🖥️ How Displayed on Screen
  • frontend/src/pages/HeatMap.jsx: Ward selector, tree count slider, temperature dial, and cooling delta badge.
  • frontend/src/components/UrbanHeat2DMap.jsx: Interactive Leaflet map displaying color-coded temperature polygons over Vadodara.
  • frontend/src/components/TreeCanopy3D.jsx: WebGL 3D view using Three.js rendering trees, animated sun rays, and cooling air currents.
🔄 Step-by-Step Data Flow Pipeline
1 User selects "Makarpura Industrial Area" (hot baseline of 41.2°C) on HeatMap.jsx.
2 User slides the tree control to simulate planting 12,500 Neem trees.
3 heatController.js calculates a -2.4°C cooling benefit, dropping the estimated surface temperature to 38.8°C.
4 The 2D Leaflet map shifts the ward boundary color from bright red to warm amber-orange.
5 The 3D canvas populates lush green trees and casts animated shadows over the neighborhood model.

💧 Module 4: Smart Irrigation Timer & MGVCL Power Roster
Water Conservation & Electricity Timing
🎯 What It Does (In Simple Words)
Calculates the exact number of water liters a field needs and how many minutes to run the water pump. It bases this on the crop type (Cotton, Banana, Tomato, Tuver), the local soil type (Goradu Sandy Loam vs Black Cotton Soil), and farm size. It also syncs directly with the MGVCL 8-hour 3-phase agricultural power schedule (Day vs Night Shift) and rings a clear sound alarm when watering is finished so no water or power is wasted.
📥 Where Data Comes From
  • Crop Water Factors ($K_c$): Standard crop water consumption rates (Cotton 0.85, Banana 1.10, Pigeon Pea 0.70, Tomato 0.95).
  • Soil Water Capacity: Goradu Sandy Loam (drains quickly) vs Black Cotton Soil (holds moisture longer).
  • MGVCL Power Roster: Vadodara rural 3-phase power shift schedule (Day: 08:00 - 16:00, Night: 22:00 - 06:00).
  • Farmer Inputs: Field acreage (e.g. 3.5 Acres) and irrigation method (Drip, Sprinkler, or Flood).
⚙️ How Processed & Backend Files
  • backend/src/routes/irrigationRoutes.js: Exposes POST /api/irrigation/calculate and POST /api/irrigation/log.
  • backend/src/models/IrrigationLog.js: Stores irrigation history records in the database.
  • Water Math: Liters = Acreage × 4046.86 m² × ET₀ (4.5mm) × Kc × (1 - SoilFactor) × Efficiency.
  • Pump Runtime: Minutes = Total Liters / (Pump Motor Output Liters/Minute).
💾 Where Data is Stored
  • MongoDB Atlas Collection: irrigationlogs
  • Mongoose Model: backend/src/models/IrrigationLog.js
  • Stored Schema Fields: crop, soilType, acreage, waterRequiredLiters, recommendedMinutes, method, powerShift, completedAt, litersSaved.
  • Live Timer State: Active ticking countdown clock stored in browser state.
🖥️ How Displayed on Screen
  • frontend/src/pages/IrrigationTimer.jsx: Dropdowns for crop and soil, large circular countdown clock, Start/Pause controls, and MGVCL power shift indicator.
  • Web Audio Chime: Sounds an audible bell alarm through the speaker when the timer hits zero so the farmer shuts off the pump motor.
  • Water Saved Counter: Displays cumulative liters preserved compared to unmanaged flood irrigation.
🔄 Step-by-Step Data Flow Pipeline
1 Farmer enters farm details: 3.5 Acres of Cotton in Goradu Sandy Loam soil on IrrigationTimer.jsx.
2 The system calculates: 28,500 Liters needed, taking 48 Minutes on a standard 5HP borewell pump.
3 Farmer taps "Start Irrigation" — the circular timer starts counting down and verifies current MGVCL power availability.
4 When the timer reaches 00:00, the pump shutdown chime sounds to prevent over-watering.
5 The watering session and estimated liters saved are saved to MongoDB Atlas collection irrigationlogs.
⛅ Module 5: Agro-Weather Observatory & IMD Alerts
Weather Intelligence & Early Warning
🎯 What It Does (In Simple Words)
Provides localized weather forecasts for Vadodara District (temperature, rainfall likelihood, humidity, wind speed) and broadcasts emergency weather bulletins from the IMD (India Meteorological Department) Ahmedabad. It warns farmers about upcoming summer heatwaves (लू), unseasonal winter rains (માવઠું), and tells them whether today's wind speed is calm enough to safely spray pest remedies without chemical drift.
📥 Where Data Comes From
  • Open-Meteo Weather API: Live hourly and 7-day weather forecasts for Vadodara coordinates (22.3072°N, 73.1812°E).
  • IMD Ahmedabad Bulletins: Official meteorological warnings regarding heatwaves, unseasonal rain (Mavthu), and storms.
  • Admin Emergency Broadcasts: Urgent warnings pushed in real time via the Operations Console.
⚙️ How Processed & Backend Files
  • backend/src/routes/weatherRoutes.js: Handles GET /api/weather/current and GET /api/weather/alerts.
  • backend/src/models/WeatherAlert.js: Filters active warnings and verifies expiration timestamps.
  • Spraying Advisory Logic: Checks if wind speed is under 15 km/h (safe to spray) or too gusty (wastes pesticide spray).
💾 Where Data is Stored
  • MongoDB Atlas Collection: weatheralerts
  • Mongoose Model: backend/src/models/WeatherAlert.js
  • Stored Schema Fields: severity ('info' | 'warning' | 'severe'), title, titleGu, message, messageGu, source, validUntil, isActive.
  • Offline Fallback: Pre-loaded IMD heat advisory loads if internet is temporarily lost.
🖥️ How Displayed on Screen
  • frontend/src/pages/Weather.jsx: Atmospheric dials (Temperature, Humidity, Wind, UV Index, Heatwave risk gauge, 7-day hourly forecast).
  • frontend/src/components/AlertCard.jsx: High-visibility warning banner across Home and Weather pages.
  • Bilingual Display: Gujarati weather terminology (ગરમીની ચેતવણી - Heat Alert, ભેજ - Humidity, પવનની ઝડપ - Wind Speed).
🔄 Step-by-Step Data Flow Pipeline
1 Farmer opens Weather.jsx; the page calls Open-Meteo for live Vadodara temperature and wind speed.
2 The frontend also queries /api/weather/alerts to retrieve active emergency bulletins.
3 Backend checks MongoDB Atlas weatheralerts for non-expired alerts (validUntil > now).
4 The 7-day forecast curve renders alongside a spraying advisory badge ("Safe to spray: wind is 8 km/h").
5 If an active heat advisory exists, an alert banner is displayed at the top of the screen in English and Gujarati.
🚜 Module 6: Krishi Tools & Equipment Marketplace (i-Khedut Subsidies)
Farm Tool Sharing & Government Subsidies
🎯 What It Does (In Simple Words)
An equipment rental portal connecting small farmers in Vadodara with Custom Hiring Centers (CHCs) across all 7 talukas. It automatically calculates Gujarat State i-Khedut Portal Subsidies (40% to 60%) for modern farm machinery (such as crop spray drones, rotavators, laser land levelers, and solar pumps), so the farmer only pays their subsidized portion and gets an instant booking confirmation.
📥 Where Data Comes From
  • CHC Machinery Catalog: Machine specifications, daily rental rates, and hub locations across Padra, Karjan, Dabhoi, Savli, Waghodia, Shinor, and Vadodara.
  • Gujarat i-Khedut Rules: Government subsidy slabs (40% standard farmer subsidy, 50-60% small/marginal farmer subsidy).
  • Farmer Booking Form: Rental days, requested start date, farm size, and contact details.
⚙️ How Processed & Backend Files
  • backend/src/routes/equipmentRoutes.js: Handles GET /api/equipment, POST /api/equipment/book, and GET /api/equipment/bookings/:userId.
  • Calculates total rental cost, deducts the i-Khedut government subsidy discount, and computes the net payable amount.
  • Generates a unique booking reference code (e.g. HRT-EQ-2026-8492).
💾 Where Data is Stored
  • MongoDB Atlas Collections: equipments and equipmentbookings
  • Mongoose Models: backend/src/models/Equipment.js and backend/src/models/EquipmentBooking.js
  • Stored Schema Fields: farmerId, equipmentId, startDate, durationDays, grossRent, subsidyApplied, netPayable, bookingRef, status.
  • Auto-Seeding: 6 standard machines are automatically seeded on server launch.
🖥️ How Displayed on Screen
  • frontend/src/pages/Marketplace.jsx: 6 machinery catalog cards (Drone, Rotavator, Laser Leveler, Solar Pump, Harvester, Drip Kit).
  • Interactive Booking Modal: Shows a transparent price breakdown (Gross Rent - 50% State Subsidy = Net Farmer Cost).
  • frontend/src/services/equipmentService.js: Sends booking request payload to backend.
🔄 Step-by-Step Data Flow Pipeline
1 Farmer selects "Precision Agro Drone Sprayer" (₹1,800/day) on Marketplace.jsx.
2 Modal computes: 3 days = ₹5,400 gross. Applied i-Khedut 50% subsidy saves ₹2,700; Net farmer payable is only ₹2,700.
3 Farmer enters date and clicks "Confirm Booking"; equipmentService.js sends data to POST /api/equipment/book.
